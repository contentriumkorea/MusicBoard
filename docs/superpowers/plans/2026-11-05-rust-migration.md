# MusicBoard Rust 이전

승인 범위: 기존 화면 유지 + Rust로 전환, 업데이트 배포. 기존 MusicBoard 프로젝트에서 진행하며 빈 r-rust 폴더로 자료를 복사하거나 기존 사용자 보관함을 변경하지 않는다.

## 구현

1. 기존 React 화면·Web Audio 재생 동작은 유지한다. Tauri 2 네이티브 실행부와 Rust 파일/저장/파형/업데이트 서비스를 추가한다.
2. 기존 `Luma Music/state.json` 형식·곡 ID·폴더·재생목록·설정·길이 편집을 보존한다. 원본 음원은 읽기만 한다.
3. Rust 미디어 서버는 127.0.0.1의 임시 포트와 임의 토큰으로만 접근하며 보관함 ID에 등록된 음원/앨범아트만 제공한다. Range/HEAD 및 스트리밍 읽기를 지원한다.
4. 기존 `window.luma` 인터페이스를 Rust IPC에 연결한다. 외부 파일 드롭은 네이티브 경로와 화면 위치를 연결한다. 내부 곡 이동은 기존 화면 동작을 유지한다.
5. Mac 기존 업데이터가 요구하는 SONO 실행 파일·앱 ID·버전·서명·실행 확인을 유지한다. Windows 기존 NSIS 업그레이드 식별자를 보존하는 설치 패키지를 만든다.
6. GitHub에서 Rust 단위 검사/컴파일 및 Windows·Mac 설치 패키지 검증을 마친 뒤 정식 배포한다. 검증 실패 시 현재 공개 버전을 유지한다.

## 검증과 의존성

- 로컬 Rust/Cargo·MSVC 도구가 확인되지 않았다. 로컬 시스템 설치를 추가하지 않고 CI Rust 환경에서 컴파일/검증한다.
- 기존 프런트엔드 검사와 Rust의 저장/가져오기/파형/범위 요청/업데이트 무결성 검사를 함께 수행한다.
- 격리된 데이터와 합성 음원으로 실제 네이티브 앱·재생·이전 데이터·재실행·원본 해시 보존을 확인한다. 사용자 개인 Mac 조작과 CI 결과를 구분한다.
- 기록은 기존 docs/검증결과.md를 사용한다. 새 라이브러리·앱 버전·검증 결과·미완료 사항을 실제 결과에 맞춰 갱신한다.
